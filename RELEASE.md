## Release ONDEWO SIP Csharp Client 5.7.2

### New Features

* [[OND236-120]](https://ondewo.atlassian.net/browse/OND236-120) Keycloak token provider with offline-token start-up, matching ondewo-sip-client-python 5.7.2: the client config takes a Keycloak *offline* refresh token instead of a password, and the provider then starts with a `grant_type=refresh_token` exchange and never sends a password grant. A Keycloak config needs a password OR a refresh token; when both are set the token wins, and a refused token is never answered with a password login. The token is redacted like the password and takes part (hashed) in the shared-provider registry key, so two configs of different tenants never share a provider. In `auth/KeycloakTokenProvider.cs` and `auth/KeycloakTokenProviderRegistry.cs`, configured through `OndewoClientConfig` and used by `OndewoChannelFactory`.

### Bug Fixes

* [[OND236-120]](https://ondewo.atlassian.net/browse/OND236-120) Keycloak token refresh survives every failure: a failed refresh backs off with full jitter from 5 s doubling up to 300 s, the background and the per-call refresh share that backoff, and a success resets it. A token that is still valid keeps being served when its refresh fails inside the 30 s expiry leeway; only an EXPIRED token raises the Keycloak authentication error, whatever failed underneath (unreachable endpoint, timeout, a non-2xx status, a body that is not a JSON object, a missing `access_token`, a non-numeric `expires_in`). A malformed response changes no provider state. The token-endpoint timeout is 10 s, quoted error bodies are cut at 500 characters, and no credential reaches a log line or an error message.
* [[OND236-120]](https://ondewo.atlassian.net/browse/OND236-120) A NaN backoff jitter counts as 0, so the delay is the 5 s base instead of NaN.

### Improvements

* Tracking API Version [5.7.0](https://github.com/ondewo/ondewo-sip-api/releases/tag/5.7.0) ( [Documentation](https://ondewo.github.io/ondewo-sip-api/) )
* [[OND236-120]](https://ondewo.atlassian.net/browse/OND236-120) Tests: the cases of the python SDK's `test_keycloak_refresh_resilience.py` and `test_client_config_refresh_token.py`, ported to `KeycloakTokenProviderTests.cs` and `KeycloakConfigAndRegistryTests.cs`, plus this SDK's edge cases.

## Release ONDEWO SIP Csharp Client 5.5.0

### New Features

* Generated from [ONDEWO SIP API 5.5.0](https://github.com/ondewo/ondewo-sip-api/releases/tag/5.5.0). The `Sip`
  service and its messages now carry (see the API release notes for the semantics):
  * Answering machine detection: status `OutgoingCallAnsweringMachineDetected`, `AnsweringMachineDetectionResult`,
    `SipStatus.AmdResult`, `SipEndCallRequest.EndReason` / `AmdResult` and the `SipReportAnsweringMachineDetected`
    RPC.
  * Call identity: `SipStatus.CallId`, scoped with the `x-ondewo-expected-call-id` gRPC metadatum.
  * Call-scoped media control: the `SipSetCallMediaControl` RPC (`SipSetCallMediaControlRequest`,
    `MediaControlSetting`, `MediaControlOwner`), reported in `SipStatus.BotMuted` / `ListeningPaused`.
  * Live call audio: the bidirectional streaming RPC `SipStreamCallAudio` (`SipCallAudioRequest` /
    `SipCallAudioResponse` and their config, frame, started, stats and ended messages), counted in
    `SipStatus.CallAudioStreams`. The generated client exposes it as an `AsyncDuplexStreamingCall`.
  * Truthful transfers: `SipTransferCallRequest.OutcomeTimeoutMs`, `SipStatus.SipResponseCode` and
    `EndCallReason.Transferred`.
  * `SipGetSipStatus` and `SipGetSipStatusHistory` declare `idempotency_level = NO_SIDE_EFFECTS`, readable from
    the generated method descriptors.
* The API change is purely additive: code built against 5.4.x compiles and stays wire-compatible.

### Improvements

* Tests: the SIP-specific suite covers the three new RPCs, the bidirectional stream, the new oneof, enum values and
  fields, and pins that only the two status reads declare `NO_SIDE_EFFECTS`.
* The stubs are generated by [ondewo-proto-compiler 5.15.5](https://github.com/ondewo/ondewo-proto-compiler/releases/tag/5.15.5)
  (previously 5.15.2).
* Tracking API Version [5.5.0](https://github.com/ondewo/ondewo-sip-api/releases/tag/5.5.0) ( [Documentation](https://ondewo.github.io/ondewo-sip-api/) )

## Release ONDEWO SIP Csharp Client 5.4.1

### New Features

* TLS and mutual TLS: `OndewoClientConfig` and `OndewoChannelFactory.Create` (namespace
  `Ondewo.Sip.Client.Connection`) build the `GrpcChannel` the generated service clients take, with the rules of the
  ONDEWO Python client. **They exist only in the new `net10.0` target of the package**; the `netstandard2.0`
  target (.NET Framework, older .NET) does not contain them, because `SocketsHttpHandler`,
  `SslClientAuthenticationOptions` and `X509Certificate2.CreateFromPem` do not exist there.
  * `grpcCert`, `grpcClientCert` and `grpcClientKey` hold PEM content, not file paths; a certificate field
    without a PEM certificate in it is refused with `ArgumentException`.
  * With `grpcCert` set only those CAs are trusted, otherwise the platform trust store; the host is always
    checked against the certificate's SAN.
  * `grpcClientCert` / `grpcClientKey` are both-or-neither (refused in the constructor); empty strings on both
    mean plain TLS. The key must be an unencrypted PEM key (PKCS#8, PKCS#1 or SEC1).
  * `useSecureChannel: false` with a client identity is refused; a plaintext channel logs a warning naming
    `host:port` through `GrpcChannelOptions.LoggerFactory`.
  * No exception message renders a PEM or the key; `OndewoClientConfig.ToString()` redacts the key.
  * Bare IPv6 literal hosts are bracketed; CRLF PEMs work.
  * Channel defaults: keepalive ping every 30 s with a 20 s ping timeout, only while calls are active; 5 s maximum
    reconnect backoff; 2^31-1 maximum message size. Not configured (documented in the README): a per-method retry
    policy, `max_pings_without_data` and `TCP_USER_TIMEOUT`, which `Grpc.Net.Client` does not expose.

### Improvements

* The package now targets `netstandard2.0` and `net10.0`. The `netstandard2.0` target is unchanged: the
  generated stubs and `OndewoAuth`.
* README: new section "TLS, mutual TLS and certificates" (modes, rules, example, channel defaults, a test PKI
  with openssl, security notes, troubleshooting).
* Tests: real TLS and mutual TLS handshakes against an in-process Kestrel server with a PKI built at test time
  (custom CA, client chain, CRLF, IPv6, missing / unrelated client identity, wrong CA, wrong host name, system
  trust store, plaintext), and a test that pins the release-notes slice of `RELEASE.md` the GitHub release is
  cut from.
* The stubs are generated by [ondewo-proto-compiler 5.15.2](https://github.com/ondewo/ondewo-proto-compiler/releases/tag/5.15.2)
  (previously 5.15.1).
* Tracking API Version [5.4.0](https://github.com/ondewo/ondewo-sip-api/releases/tag/5.4.0) ( [Documentation](https://ondewo.github.io/ondewo-sip-api/) )

## Release ONDEWO SIP Csharp Client 5.4.0

### New Features

* Initial release of the ONDEWO SIP C# client. The package `Ondewo.SIP.Client` ships the
  gRPC message and client stubs generated from the [ONDEWO SIP API](https://github.com/ondewo/ondewo-sip-api)
  by the `ondewo-csharp-proto-compiler` image of
  [ondewo-proto-compiler 5.15.1](https://github.com/ondewo/ondewo-proto-compiler): one
  `<Message>.cs` per proto plus one `<Service>Grpc.cs` per proto that declares a service, nested by C# namespace
  under `api/`.
* The package targets `netstandard2.0`, so it is consumable from .NET Framework 4.6.1+, .NET Core 2.0+ and every
  modern .NET, and carries `Google.Protobuf`, `Grpc.Net.Client`, `Grpc.Core.Api` and `Google.Api.CommonProtos` as
  its only dependencies. The `google/api`, `google/rpc` and `google/type` descriptors the API imports come from
  `Google.Api.CommonProtos` rather than being generated a second time into this assembly.
* `make build` is the whole pipeline — submodule checkout at the pinned versions, compiler image build, stub
  generation and `dotnet pack` — and `make ondewo_release` cuts the GitHub and NuGet release from the same
  version number.
